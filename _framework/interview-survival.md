# Interview Survival — Minimum Viable Answers

One answer per layer. You can say this truthfully after completing 2-3 atoms — before the layer is fully done.

Update the answers as your depth grows. Strike through old versions, add new ones below.

---

## Layer 1 — How the web works

> "A client sends an HTTP request to a server — a URL, a method like GET or POST, sometimes a body. The server processes it and returns a response with a status code and data, usually JSON."

---

## Layer 2 — SQL + databases

> "I can write SELECT queries with WHERE clauses and JOINs. I understand relational data — tables linked by foreign keys. I've designed and queried a real schema."

---

## Layer 3 — Backend basics

> "A backend is a server that listens for requests, runs logic, and returns data. I've built a Node.js endpoint that receives webhook events and writes them to a database."

---

## Layer 4 — APIs in depth

> "I understand REST — resources are URLs, actions are HTTP methods, auth is usually an API key or OAuth token in the header. I've integrated with real webhooks."

---

## Layer 5 — Frontend basics

> "The frontend is JavaScript running in the browser. It fetches data from the backend via fetch() and renders it. I've built a simple dashboard that displays live data."

---

## Layer 6 — Deployment

> "I've deployed a Node.js app to [Vercel/Railway]. I understand the difference between staging and production, and how environment variables keep secrets out of the codebase."

---

## Layer 7 — AI/LLM Integration

> "I understand how LLM APIs work — you send a prompt, get a completion back. Tool use lets the model call your code. I've built a RAG-lite pattern where a user query hits a database and the results are sent to Claude as context for a grounded answer."

---

## GitHub

> "I use branches for features, commit with descriptive messages, and open PRs for review. I can read a diff and explain what changed and why. I understand worktrees for parallel branch work."
